- 2026-11-14: **Main arms = ccReject → ccRepair → ccRepairDel → ccAucRepair** (Holm family of 4; amendment before any filter arm was trained). Reasons (user + discussion):
  - **cc instead of touch:** touch v1 and v2 give identical volume classes on all 999, so a touch repair and the cc repair differ only by detached liver pieces (179 vols, p95 0.6 ml); training both would cost ~7 GPU h for a difference far below the 0.01 noise floor. cc ("the liver is one organ, a tumour lies in it") is the cleaner definition and also tidies the liver label.
  - **ccReject = 343 (strict twin of ccRepair), not 401 (tumours only):** keeps the principle that reject = exactly the volumes the repair leaves unchanged, so reject vs repair differ only in the action. Costs 58 volumes whose only issue is a liver speck.
  - **ccRepairDel (842):** ccRepair without the 157 volumes left tumour-free. With ccReject and ccRepair it forms a chain in which each step adds one kind of volume (clean 343 → + repaired with tumour 842 → + tumour-free 999); ccRepair vs ccRepairDel asks whether clean negatives cut FPs (`all` predicts tumour in 10/10 tumour-free test cases).
  - **AUC only on top of cc (ccAucRepair), no AUC-only arms:** at cut 0.547, 218 of the 267 AUC-failing volumes also fail touch, and 190 of the 349 AUC-failing components already lie outside the main structure. AUC's own contribution is the 159 invisible tumour labels inside the liver (141 volumes; 19 more volumes become tumour-free, 157 → 176). ccAucRepair vs ccRepair isolates exactly that. AUC-only arms go to the backlog.
  - **lits_049 excluded from the real reference (whole case) → cut 0.547:** none of its least visible lesions shows anything under the label (review figures, core vs shell HU 116/118), i.e. unreliable labels; it is the only real case below 0.547, and 0/681 real test lesions lie below 0.547, so the cut picked on val is confirmed on test. At 0.504 the AUC rule changes only 31 volumes (below what can show above the noise).
  - **Liver HU/border check dropped as a filter:** blind review score: flagged 30/60 → 28 ok, 2 unsure, 0 bad; the only bad liver (B21) unflagged. The border-step flag measures edge softness, not wrong labels. Kept descriptive.
  - **Naming technique first, action second** (ccReject, ccRepair, ccRepairDel, ccAucRepair, aucReject, ...); datasets renamed too (D103 RepairCC, D104 RepairCCAUC). Reason: user.
  - **Preprocessing in the GPU session, overlapped with training:** a full-B200 session has more cores (48-core quota) and costs less than the biggest CPU session; ccReject (D101 fold) trains while D103/D104 are built + preprocessed, so the GPU doesn't idle. Replaces the 11-12 "repair first, GPU idle at start accepted" and the separate CPU session 2. Reason: user.
